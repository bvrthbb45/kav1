# ארכיטקטורה

```
דפדפן (Alpine.js, קבצי HTML ב-frontend\web)
   │  HTTP + עוגיה kav1_session     WebSocket /ws (רענון חי)
   ▼
FastAPI (backend\app\main.py)
   ├─ routes_auth.py        התחברות, התנתקות, /auth/me
   ├─ routes_admin*.py      משתמשים, תפקידים, הגדרות, גיבוי, יומן
   ├─ routes_categories.py  ניהול קטגוריות (מפתחות ב-properties)
   ├─ routes_reports.py     דוחות וייצוא
   ├─ routes.py             מבקרים: רשימה, חיפוש, כניסה/יציאה, עריכה
   ├─ visitor_extras.py     (חדש) /visitors/overview: כניסה אחרונה, פרויקט, תוקפים
   └─ routes_locations.py   (חדש) מתגי פיצ'רים, מפות, מלווים ומיקומים
   │
   ├─ dependencies.py       get_current_user, require_permission
   ├─ seed.py               טוען את קטלוג ההרשאות ותפקיד המנהל בכל הפעלה
   ▼
SQLite: backend\local_database.db   (קובץ אחד)
```

## עקרון המבנה: רק הוספה

* מסכים קיימים נשארים עם אותו עיצוב (`kav1.css`) ואותה התנהגות. נוספו עמודות, סינון וחלון, ולא הוחלף דבר.
* כל פיצ'ר חדש יושב בקובץ חדש. הקבצים הקיימים קיבלו שורות בודדות (למשל 3 שורות ב-`main.py`).
* טבלאות חדשות בלבד: `kav1_feature_flags`, `location_maps`, `location_entries`. אף טבלה קיימת לא שונתה, ואף שורה לא נמחקת.
* הפיצ'רים האופציונליים כבויים עד שמנהל מפעיל אותם, וכשכבויים ה-API שלהם מחזיר 404.
* מידע על מבקר (פרויקט, תוקפים, אבטחת מידע) נשאר ב-`visitors.properties` (JSON חופשי), בלי שינוי סכמה.

## מה עובר בהפעלה

1. `run_server.bat` ← `migrate_db.py` (טבלאות והרשאות, בלי מחיקות).
2. `app.main`: יוצר טבלאות חסרות, `run_seed` (קטלוג הרשאות + מנהל), ו-`ensure_locations_permissions` (שתי הרשאות חדשות למנהל).
3. בסגירה נקייה: איחוד קובץ ה-WAL (אם קיים) לקובץ הראשי.

## זרימת בקשה בשני מסכים

* **פאנל שליטה / מבקרים:** הדף טוען `/visitors` (כרגיל), ואז `/visitors/overview` (תוספת, שאילתה אחת מקובצת) וממזג בצד הלקוח: סדר, פרויקט, תגי תוקף, קיבוץ. אם התוספת נכשלת, הרשימה נראית כמו קודם.
* **שמירת מבקר:** `PUT /visitors/{id}` כרגיל. כשהמתג "חובה לבחור אבטחת מידע" פועל, השרת בודק את שלושת הערכים ואת תוקף האישור ומחזיר 400 עם הסבר.
